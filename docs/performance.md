# 性能检查与优化

历史搜索使用 KMP 匹配，人工加粗字形复用光栅化缓冲区。Gio 和 MyGo 也同步优化了连续输出与回滚存储。

## 已完成

### 历史搜索

`internal/ui/pane.go` 原先先为整行生成 rune 和列号数组，再逐位置比较查询。未找到结果时，回绕搜索还可能再次扫描已经访问的历史行。重复前缀的查询会反复比较相同字符，最坏时间复杂度为 O(文本长度 × 查询长度)。搜索期间持有窗格锁，耗时也会影响输出解析。

现在直接遍历单元格，使用 KMP 匹配，并只保留查询长度的列号窗口；将回绕前后的行范围分开，每行最多扫描一次。保留每个显示行的第一个匹配、正向/反向回绕、空白单元格，以及组合字符和宽字符的原有选择位置。

### 人工加粗字形

`internal/render/atlas.go` 的人工加粗需要把同一轮廓绘制五次。原先每次创建光栅器，都会分配覆盖率工作缓冲区；现在在五次绘制之间调用 `Reset`，清空并复用同一缓冲区。复用范围限定在一次字形光栅化内，不增加长期缓存。

## 测量结果

Windows/amd64，Go 1.27.4，Intel Xeon E3-1240 V2。每项运行三次，以下取中位数。搜索使用 120 列、24 行可见区和 8000 行已填满的历史；表中三项搜索均为未命中场景。

| 场景 | 修改前耗时 | 修改后耗时 | 修改前临时分配 | 修改后临时分配 |
| --- | ---: | ---: | ---: | ---: |
| 普通英文日志搜索 | 45.75ms | 9.25ms | 3056B / 15 次 | 128B / 2 次 |
| 中文、重音和 emoji 日志搜索 | 48.87ms | 11.27ms | 3056B / 15 次 | 0B / 0 次 |
| 重复前缀查询 | 220.61ms | 10.61ms | 3264B / 16 次 | 1040B / 3 次 |
| 32px 字形首次人工加粗光栅化 | 21.80μs | 20.25μs | 17270B / 11 次 | 4977B / 7 次 |

搜索耗时下降约 77%–95%，人工加粗的临时分配字节下降约 71%。普通字形光栅化的分配量保持 3633B / 7 次。

这些是指定工作负载的函数级基准，不能直接等同于整机 CPU、进程常驻内存或所有交互的改善比例。字形图集命中时不会重新光栅化，因此人工加粗的收益主要发生在首次遇到该字形、字号或缓存淘汰后。短查询的堆分配结果也受 Go 版本影响。

复现命令：

```powershell
go test ./internal/ui ./internal/render -run '^$' -bench 'Benchmark(FindHistory|Rasterize)$' -benchmem -benchtime=300ms -count=3
```

## 验证

- `go test ./...`、`go vet ./...` 通过。
- 搜索新增回归测试，覆盖中文、重音组合、emoji、重复前缀、空白、正反向回绕，并与朴素 rune 搜索对照查询结果和列位置。
- 在同一台机器和同一 Consolas 字体上，对 M、g、@ 三种字形，12/32/96px 三种字号，普通/人工加粗两种模式，共 18 组覆盖率位图进行修改前后 SHA-256 对比。像素、尺寸、偏移和字距全部一致。

## 连续输出与回滚存储

可见区滚动时移动行引用，复用已有的单元格存储。回滚历史只省略硬换行末尾的默认空格，同时记录列数。查找、点击选字和缩放能继续按原列位置处理这部分空格，彩色空格和软换行按原样存储。

以下是两套项目各自修改前后的中位数，每项运行三次。测试环境为 Windows amd64、Go 1.27.4 和 Intel Xeon E3-1240 V2。日志输出使用 120 列、48 行可见区和 8000 行历史。搜索使用 120 列、24 行可见区和 8000 行历史，查询词在历史中均未命中。

| 测量项 | Gio 修改前 → 修改后 | MyGo 修改前 → 修改后 |
| --- | ---: | ---: |
| 历史填满后持续输出，每行耗时 | 8.98 → 2.20 μs | 5.93 → 1.80 μs |
| 从空历史填到 8000 行，累计分配 | 38.39 → 15.22 MiB | 24.62 → 9.27 MiB |
| 英文日志搜索 | 9.32 → 3.96 ms | 10.01 → 3.78 ms |
| Unicode 日志搜索 | 12.49 → 5.15 ms | 11.73 → 4.89 ms |

累计分配采用基准测试报告的 `B/op`，包括初始化可见区及填充回滚历史时的分配。实际内存收益随默认行尾空格的比例变化。

```powershell
go test ./internal/term -run '^$' -bench 'Benchmark(ScrollOutput|FillScrollback)$' -benchmem -benchtime=400ms -count=3
go test ./internal/ui -run '^$' -bench 'BenchmarkFindHistory/(ASCII|Unicode)$' -benchmem -benchtime=400ms -count=3
```

两套项目均通过全量测试和竞态检测。回归测试覆盖彩色行尾、宽字符和组合字符、缩放时的列位置、分区滚动、同步画面，以及历史推进后的匹配位置。

## 终端绘制指令

同一个窗格绘制时，重复字符和组合字形共用已经计算的字体、图集位置和单元格内偏移。缓存由当前绘制复用，容量固定。默认背景直接取调色板值，相邻的同样式字符共用已解析的前景色。

用 120 × 42 的终端网格绘制已预热的画面，记录应用生成一帧绘制指令的时间。Windows amd64 和 Go 1.27.4 上每项运行三次，以下为中位数。

| 内容 | Gio 修改前 → 修改后 | MyGo 修改前 → 修改后 |
| --- | ---: | ---: |
| 普通日志 | 1.196 → 0.639 ms | 0.909 → 0.354 ms |
| 彩色输出 | 0.786 → 0.476 ms | 0.603 → 0.318 ms |
| 含中文、组合字符和 emoji 的输出 | 0.771 → 0.411 ms | 0.595 → 0.229 ms |

Unicode 场景中，两套版本每次绘制的临时分配均从约 7862 B、168 次降至 187 B、4 次。像素测试覆盖混合单双线与相邻字符的接缝，以及块状光标覆盖组合字符时的反色绘制。

```powershell
go test ./internal/render -run '^$' -bench '^BenchmarkDrawTerminal$' -benchmem -benchtime=450ms -count=3
```
